# Donna v0.2 — Memory Substrate

**Date:** 2026-05-06
**Status:** prototype worktree

## Working Criteria

Donna memory is working when she can:

- remember stable user facts after restart
- know the current situation without being retold every turn
- recall past chunks of the ongoing WhatsApp thread
- track unresolved commitments and questions
- accept corrections by marking old memory inactive
- trace memory back to source chat sequence numbers
- keep normal turns fast by doing extraction after `send_burst`
- rebuild derived memory from `chat_messages`

## Architecture

`chat_messages` remains the immutable raw ledger. Everything else is derived.

```text
chat_messages
  -> episodes
  -> facts + open_loops
  -> user_memory_state
  -> context builder + recall tool
```

## Canonical Stores

### `episodes`

Chunked history over the ledger. For this prototype, each completed turn becomes
one episode. Later we can merge adjacent episodes into larger semantic chunks.

Important fields:

- `start_seq`, `end_seq`: source range in `chat_messages`
- `title`, `summary`, `topics`: compact retrieval surface
- `metadata`: extraction trace and external IDs

### `facts`

Durable truth claims Donna may use later.

Facts are not raw chat. They are extracted claims like:

- User is building Donna as a WhatsApp-native personal AI.
- User prefers direct technical answers.

Facts can be `active`, `superseded`, or `deleted`.

### `open_loops`

Unresolved commitments, questions, reminders, or decisions.

Open loops can be `open`, `closed`, or `snoozed`.

### `user_memory_state`

One row per user containing:

- `living_profile`: durable user model
- `situation_brief`: current working context
- `last_episode_seq`: high-water mark for episode creation
- refresh timestamps

## External Memory

This prototype uses **mem0 only**, not Graphiti.

Postgres remains canonical. mem0 is optional and used as a semantic lane:

- after episode creation, write the episode summary to mem0 if `MEM0_API_KEY` is set
- during `recall`, search mem0 alongside Postgres if configured
- if mem0 is unavailable, Donna still works from Postgres

## Post-Turn Worker

After `send_burst` and `chat_messages` persistence:

1. Find new chat messages after `user_memory_state.last_episode_seq`.
2. Summarize the new range into an episode.
3. Extract facts and open loops from the episode.
4. Upsert extracted rows into Postgres.
5. Write the episode to mem0 if configured.
6. Refresh `situation_brief` every episode.
7. Refresh `living_profile` when facts changed or profile is stale.

The worker is best-effort. Extraction failures must not lose the raw ledger.

## Recall Tool

One tool:

```text
recall(query, scope?)
```

Scopes:

- `auto`
- `episodes`
- `facts`
- `open_loops`

Recall searches Postgres first and includes mem0 semantic results when available.

## Non-Goals

- Graphiti
- MCP
- pgvector
- perfect conversation boundary detection
- proactive scheduling
- multi-user auth/RLS

Those are future passes. This worktree tests the smallest memory substrate that
still supports situational awareness.
