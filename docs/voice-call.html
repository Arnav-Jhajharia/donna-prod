donna
voice call architecture · livekit + elevenlabs + callkit · v0.1

what this is

donna calls you

this document describes the stack that turns "user taps ring me" into an actual phone-ring on their device, with donna's voice on the other end. it covers iOS frameworks (pushkit, callkit), the livekit infrastructure (rooms, agents), elevenlabs (donna's voice), the claude reasoning loop, and how everything she hears gets persisted as memory. read top-to-bottom or jump to a section.

the stack at a glance

five things doing five jobs

none of these are new tech. all of them are stable in 2026. the work is wiring them together, not inventing them.

trigger

pushkit + apns

apple's voip push delivery. wakes a closed app within ~5s. requires the voip push entitlement.

ui

callkit

renders the native incoming-call screen. ringtone, lock screen, phone-app integration. apple owns the design.

transport

livekit (webrtc)

real-time bidirectional audio between phone and our backend. opus codec. ~$0.0003/participant-minute on cloud.

voice

elevenlabs streaming tts

donna's voice. low-latency streaming, custom voice clone available. integrated as a livekit agent plugin.

brain

claude (anthropic)

drives the conversation. listens via stt (whisper or livekit-bundled), thinks, writes responses for tts.

persistence

donna memory

post-call: transcript + claude's synthesis become first memory entries. via graphiti or zep, tbd.

nine steps. the slow ones are network latency (apns push delivery, oauth tts streaming start). the rest is microseconds.

part one — the receiving end

what happens on the iphone

three apple frameworks, one third-party rn library each. all of this requires a dev build (not expo go) because pushkit + callkit need real entitlements that only exist in a binary apple signs.

pushkit — the special push

regular APNs pushes can't wake a killed app reliably. voip pushes can. apple grants this only to apps that have a real calling feature. the device receives a voip push, the os wakes our app to process it. we have ~5 seconds before ios assumes we've failed and terminates us.

AppDelegate.swift — voip push registration 
import PushKit

class AppDelegate: UIResponder, UIApplicationDelegate, PKPushRegistryDelegate {
  var voipRegistry: PKPushRegistry?

  func application(_ application: UIApplication,
                   didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
    voipRegistry = PKPushRegistry(queue: .main)
    voipRegistry?.delegate = self
    voipRegistry?.desiredPushTypes = [.voIP]
    return true
  }

  func pushRegistry(_ registry: PKPushRegistry,
                    didUpdate pushCredentials: PKPushCredentials,
                    for type: PKPushType) {
    // upload pushCredentials.token to backend — this is the voip token
    let token = pushCredentials.token.map { String(format: "%02x", $0) }.joined()
    BackendClient.shared.registerVoipToken(token)
  }

  func pushRegistry(_ registry: PKPushRegistry,
                    didReceiveIncomingPushWith payload: PKPushPayload,
                    for type: PKPushType,
                    completion: @escaping () -> Void) {
    // MUST report to callkit within ~5 seconds or ios terminates us
    let dict = payload.dictionaryPayload
    let roomToken = dict["roomToken"] as? String ?? ""
    CallManager.shared.reportIncomingCall(from: "donna", roomToken: roomToken)
    completion()
  }
}

callkit — the native call ui

callkit is what makes the phone actually ring with the system call ui. it integrates with lock screen, do-not-disturb, ringtones, the phone app's call history. we don't design it — apple does. our job is just to report calls correctly.

CallManager.swift — callkit provider 
import CallKit

class CallManager: NSObject, CXProviderDelegate {
  static let shared = CallManager()
  private let provider: CXProvider

  override init() {
    let config = CXProviderConfiguration(localizedName: "donna")
    config.supportsVideo = false
    config.supportedHandleTypes = [.generic]
    config.maximumCallsPerCallGroup = 1
    config.includesCallsInRecents = false  // donna doesn't show in recents
    provider = CXProvider(configuration: config)
    super.init()
    provider.setDelegate(self, queue: .main)
  }

  func reportIncomingCall(from caller: String, roomToken: String) {
    let uuid = UUID()
    let update = CXCallUpdate()
    update.remoteHandle = CXHandle(type: .generic, value: caller)
    update.hasVideo = false
    update.localizedCallerName = "donna"

    provider.reportNewIncomingCall(with: uuid, update: update) { [weak self] error in
      if error == nil {
        // user will see the native incoming call ui
        ActiveCallStore.shared.pending = (uuid, roomToken)
      }
    }
  }

  func provider(_ provider: CXProvider, perform action: CXAnswerCallAction) {
    // user tapped "answer"
    guard let pending = ActiveCallStore.shared.pending else { return }
    LiveKitManager.shared.joinRoom(token: pending.roomToken)
    action.fulfill()
  }

  func provider(_ provider: CXProvider, perform action: CXEndCallAction) {
    LiveKitManager.shared.leaveRoom()
    action.fulfill()
  }

  func providerDidReset(_ provider: CXProvider) {
    LiveKitManager.shared.leaveRoom()
  }
}

livekit ios sdk — the actual audio

once callkit hands us the "user answered" event, we join a livekit room. the room is a webrtc session. donna (running server-side) is the other participant. audio flows both ways. when the user hangs up, we leave the room.

LiveKitManager.swift — minimal room handling 
import LiveKit

class LiveKitManager {
  static let shared = LiveKitManager()
  var room: Room?

  func joinRoom(token: String) async throws {
    let url = "wss://donna.livekit.cloud"
    let room = Room()
    self.room = room
    try await room.connect(url: url, token: token)
    // microphone publishes automatically when audio session activates
  }

  func leaveRoom() {
    Task { await room?.disconnect(); self.room = nil }
  }
}

the 5-second rule

between receiving the voip push and calling reportNewIncomingCall, you have ~5 seconds. miss it and ios terminates the app. miss it repeatedly and apple stops delivering voip pushes to your app at all. this is the most fragile contract in the whole stack. register pushkit in AppDelegate (native), not from javascript — js bridge startup can blow the deadline.

part two — the calling end

what happens on the backend

two pieces. a stateless trigger endpoint that sends the voip push, and a livekit agent that runs the conversation. the agent is where most of the interesting code lives.

the trigger — sending a voip push

when the user taps "ring me," the app POSTs /call/start to our backend. the backend sends a voip push via apns to the user's device. the push payload contains the livekit room name and a join token. the device receives the push within ~200ms typically.

backend/call_trigger.py 
import apns2
from livekit import api

async def start_call(user_id: str) -> dict:
    user = await db.get_user(user_id)
    voip_token = user.voip_token  # registered at app install
    if not voip_token:
        raise ValueError("user has no voip token — push not granted yet")

    # generate livekit room + tokens (one for app, one for agent)
    room_name = f"onboarding-{user_id}-{int(time.time())}"
    app_token = api.AccessToken(
        os.environ["LIVEKIT_API_KEY"],
        os.environ["LIVEKIT_API_SECRET"]
    ).with_identity(user_id).with_grants(
        api.VideoGrants(room_join=True, room=room_name)
    ).to_jwt()

    # send voip push
    payload = {
        "aps": {"alert": "donna is calling"},
        "roomToken": app_token,
        "roomName": room_name,
        "callerName": "donna"
    }
    await apns2.send_voip(
        token=voip_token,
        topic=f"{BUNDLE_ID}.voip",
        payload=payload
    )

    # dispatch agent to the room
    await dispatch_agent(room_name, user_id)
    return {"room": room_name, "status": "ringing"}

the agent — livekit's voice ai framework

livekit ships an "agents" framework that handles the voice loop for you. one python file. it joins a room, runs an stt → llm → tts pipeline, manages turn-taking, handles interruptions. we plug in claude as the brain and elevenlabs as the voice.

agent/onboarding_agent.py 
from livekit.agents import (
    AutoSubscribe, JobContext, WorkerOptions, cli, llm
)
from livekit.plugins import openai, elevenlabs, silero, anthropic
from livekit.agents.voice import Agent, AgentSession

ONBOARDING_INSTRUCTIONS = """
you are donna. you are calling the user for the first time.
your voice is quiet, editorial, intimate. no exclamation marks, no emojis,
no "great!" or "perfect!" lowercase mental register.

the call is 30-45 seconds. cover three things in order:

1. greet them by name (from context). ask "is this a good time?"
2. ask one personal question: "tell me one person i should never
   forget about you." listen carefully. ask one follow-up if their
   answer is vague.
3. end the call: "good. i'll read your inbox and calendar now.
   see you in the app in a moment."

then call the hangup tool.

if they sound rushed: cut to the personal question immediately.
if they sound confused: explain briefly, then continue.
if they hang up early: that's fine. save what you got.
"""

async def entrypoint(ctx: JobContext):
    # get user name from job metadata
    user_id = ctx.job.metadata
    user = await fetch_user(user_id)

    session = AgentSession(
        vad=silero.VAD.load(),
        stt=openai.STT(model="whisper-1"),
        llm=anthropic.LLM(model="claude-sonnet-4-6"),
        tts=elevenlabs.TTS(
            voice_id=DONNA_VOICE_ID,
            model="eleven_turbo_v2_5",
            stability=0.5,
            similarity_boost=0.75,
        ),
    )

    instructions = ONBOARDING_INSTRUCTIONS + f"\n\nuser's name: {user.first_name}."

    await ctx.connect(auto_subscribe=AutoSubscribe.AUDIO_ONLY)
    await session.start(
        agent=Agent(instructions=instructions),
        room=ctx.room,
    )

    # after session ends, persist transcript as memory seed
    transcript = session.history.to_dict()
    await save_memory(user_id, kind="onboarding_call", payload=transcript)

if __name__ == "__main__":
    cli.run_app(WorkerOptions(entrypoint_fnc=entrypoint))

that's the entire agent. ~50 lines. livekit handles the audio routing, vad (voice activity detection), stt streaming, llm calls, tts streaming, turn-taking, interruption handling. our job is the prompt and the cleanup.

memory persistence

at the end of the call, claude has access to the full transcript. we ask it to write a short structured memory summary that becomes donna's first knowledge of the user. that summary plus the raw transcript both go into the memory store.

agent/save_memory.py 
async def save_memory(user_id: str, kind: str, payload: dict):
    # raw transcript
    await memory_store.write(
        user_id=user_id,
        kind="raw_call_transcript",
        body=payload,
    )

    # synthesis — what should donna remember about this call?
    synthesis = await claude.complete(
        model="claude-sonnet-4-6",
        system=(
            "summarize the call transcript into things to remember "
            "about this person. focus on the one name they shared, "
            "any context around that person, tone, and pacing. "
            "write 3-5 short memory entries in plain text. "
            "do not invent details not in the transcript."
        ),
        messages=[{"role": "user", "content": str(payload)}]
    )

    for entry in synthesis.split("\n\n"):
        if entry.strip():
            await memory_store.write(
                user_id=user_id,
                kind="memory_entry",
                body={"text": entry.strip(), "source": "onboarding_call"},
            )

the voice script

what donna says, exactly

this is the script the agent runs. branches handle the obvious responses. anything off-script falls through to claude's discretion within the prompt's bounds.

donna: "hi, bharat. is this a good time?"

user (yes): proceed
user (no): "ok. i'll be quick. ten seconds." → proceed faster
user (silence 4s): "i can hear you. is this a good time?"

donna: "good. before i let you go, tell me one person i should
        never forget about you. someone i need to know about."

user (gives name + context): "noted. anything else about them
                              before i hang up?"
user (gives just name, no context): "okay, [name]. tell me one
                                      thing about them."
user (silence): "no rush. take your time."
user (refuses): "fair. we'll get there another way."

donna: "good. i'll read your inbox and calendar now. see you
        in the app in a moment."

[hangup tool]

the script is intentionally short — 30-45 seconds end to end. the goal is not to extract information, it's to establish the voice and capture one human memory seed. everything else donna learns from data.

setup

what to configure, in order

two-three hours of focused setup work, mostly portal configuration. one cloud build, one test call.

  1. apple developer portal → identifiers → bundle id com.donna.app → enable push notifications capability (covers regular + voip).
  2. apple developer portal → keys → create an apns auth key (.p8 file). download once. this is the backend's credential for sending pushes.
  3. livekit cloud → sign up, create a project named donna. note the API_KEY, API_SECRET, and wss://<project>.livekit.cloud url.
  4. elevenlabs → either pick a stock voice for donna or clone a custom one (provide 1-2 min of reference audio). save the voice_id.
  5. mobile/app.json → add to ios.infoPlist: 
    {
  "UIBackgroundModes": ["voip", "audio"]
}
  6. mobile: install react-native-callkeep, react-native-voip-push-notification, @livekit/react-native.
  7. mobile/AppDelegate: register pushkit in didFinishLaunchingWithOptions, not from js. upload voip token to backend on receipt.
  8. backend (donna-prod): add /call/start endpoint, apns2 client, livekit token generation.
  9. agent: deploy the python agent as a livekit worker. livekit-cli agent deploy or self-host.
  10. eas: eas build --profile development --platform ios. ~15-20min cloud build. install on phone via testflight (internal testers).
  11. test: tap "ring me" → phone should ring → answer → hear donna → hang up → memory should be written.

failure modes

what bites you

each of these we've seen documented in real production stacks. plan for them.

1 · the 5-second rule

register pushkit in AppDelegate natively. do not wait for js to mount. ios will silently start dropping your voip pushes if you miss the deadline a few times. recovery requires app reinstall.

2 · voice latency

end-to-end (user speaks → stt → claude → tts → user hears) must be under ~800ms or the conversation feels broken. livekit + elevenlabs turbo + claude streaming gets us there, but every link in the chain needs streaming enabled. test on cellular, not just wifi.

3 · voip entitlement abuse

voip pushes are only for actual calls. using them as a sneaky way to wake the app for background sync = entitlement revoked, app store rejection. report a real call to callkit every time.

4 · the call drops mid-conversation

cellular blip, app backgrounding wrong, livekit room timeout. agent must handle disconnection: save whatever transcript exists as memory, mark the call as incomplete, allow user to reconnect via the next page in the onboarding without re-starting.

5 · user denies push permission at install

no voip token = no calls. always fall through to the text onboarding path. never block onboarding on push consent.

6 · cost runaway from claude on long calls

cap call duration at 90s server-side. if claude is rambling, the agent's response token limit forces brevity. log every call's cost; alert if any single call exceeds $1.

7 · do-not-disturb / focus modes

by default, voip calls bypass dnd. users can disable this per-app in settings. respect that — if a call fails to deliver, fall back to a quiet push notification instead of retrying.

8 · spam = brand death

this isn't a technical failure mode, it's a product one. one bad-timed call breaks trust permanently. never call without a real reason. obey quiet hours. apply the "would a real chief of staff call right now?" test before any non-onboarding call. detail in the call cadence document (tbd).

open questions

still to decide

  1. self-host livekit, or cloud? cloud at v1 (cheap, zero ops). consider self-host past ~10k MAU when egress dominates costs.
  2. donna's voice — stock or cloned? stock saves $5/mo and is instant. clone takes a recording session and ~$22/mo on elevenlabs creator tier, but the brand impression is real. recommend clone for v2, stock for v1 family test.
  3. haiku for the agent, or sonnet? haiku is 10x cheaper, ~2x faster latency. for a structured script this is probably sufficient. test both, measure interruption naturalness.
  4. does the call ever happen in whatsapp instead? whatsapp business has voice api as of 2024. could send donna's voice via whatsapp voice notes. lower fidelity than callkit but no app install required.
  5. what about android? android has connectionservice (callkit-equivalent) and high-priority data messages (voip-push-equivalent). react-native-callkeep covers both. ~80% of the ios code translates. defer until ios is shipping.
  6. recording consent? the call is recorded as transcript. some jurisdictions require explicit consent. add to the call script: "i'll keep a transcript of this." add to terms.
