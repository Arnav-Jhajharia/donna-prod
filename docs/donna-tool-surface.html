donna — the tool surface

every MCP server, integration, and API we've considered for donna, grouped by what she does for the user. ~300 entries across thirteen capability clusters.

working document · last reviewed may 2026 · status: pre-wiring

what this is

this is donna's tool universe — the complete capability surface she can draw from on day one and beyond. organized by what donna does for the user, not by underlying tech. auth model, production-readiness, and a relevance score (1–5 stars) are noted per entry.

this is the working catalog. as we wire integrations, we'll mark them. as we discover new MCPs worth adding, they go here.

how donna reaches all of this

donna does not wire each of the 300 integrations one by one. she stacks five meta-platforms that each give her hundreds of tools through a single connection, plus a handful of custom-built tools for the "magic moments" no platform delivers.

stack: klavis hosted ~98 oauth integrations (primary) anthropic connectors ~414 vetted oauth (gap fillers) composio ~250 toolkits, 20k+ tools (better tool defs) pipedream MCP 3000 apps, 10k+ tools (long tail) apify MCP 3000 scrapers (web that has no api) donna-browser 1 universal browser (logged-in actions) custom tools ~12 magic moments (vapi, audd, plantnet, ...) total day-one surface: ~25,000+ callable tools

the LLM cannot see all 25,000 tool definitions at once. tool selection happens via a hybrid pattern: ~50 "hot path" tools embedded directly, the rest reached through meta-tools or retrieval. see donna brain notes.

legend

oauth requires user to grant access to their account   api key developer-held credential   public no auth required   local runs on-device or self-hosted   diy no MCP yet, build it ourselves

prod production-ready today   experimental community-grade, may break   ★★★★★ donna magic factor 1-5

the meta-platforms — how all of this connects

donna doesn't wire each integration directly. she stacks platforms that each give her many tools through one connection. this is the underlying architecture that makes the 300-tool surface tractable.

stacking these gives donna ~25,000 callable tools through ~8 connections. each platform is one integration job for us — the platforms do the hard work of authentication, rate limiting, and provider-specific quirks.

the tool-selection problem

the LLM cannot fit 25,000 tool definitions in its context. donna uses a hybrid pattern:

  • direct tools (~50 hot-path) — gmail, calendar, notion, readwise, oura, plaid, browser, search, the magic tools. always in context. fast.
  • meta-tools (the long tail) — a handful of generic invocations like pipedream_call(app, action, params), apify_run(actor, input), composio_call(tool, params). the brain picks the platform + names the underlying action.
  • tool retrieval (fallback) — every tool description embedded; at each turn, retrieve top-k relevant tools given the user's message and inject them dynamically.

build order

not every cluster lands on day one. ranked by impact-per-hour:

  1. week 1 — klavis wired, donna-browser deployed ✓, gmail/calendar/notion/readwise working through klavis. one custom magic tool (audd is the cheapest first win).
  2. week 2 — anthropic connectors integrated for Plaid + Mercury + Resy + Uber + AllTrails. apify wired for the social-media + booking + scraping cluster.
  3. week 3 — plantnet + inaturalist + ebird + opensky + flightaware (cluster 6 + 7). these are the screenshot moments.
  4. week 4 — oura/whoop (cluster 1). vapi (the phone calls moment). composio + pipedream as long-tail fallbacks.
  5. later — the custom builds: eight sleep, dexcom, owntracks, audio identification chain.
