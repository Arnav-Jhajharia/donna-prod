the whole picture

two prompts. two tiers. one user-facing thread. real work is hidden behind a routing tool.

legend: user / inbound personality agent execution agents specialists dashed = inferred / infra

one user turn, end to end

"find the menu jane sent me last week and forward it to bob"

that's the killer move. "long-lived" doesn't mean a daemon — it means the row sticks around. when poke addresses the SAME NAME, the full prior history loads automatically. no re-search. no re-derive. state is free.

the trigger system

two trigger kinds — cron and email-match. critically: a tiny classifier model decides whether something is worth waking the big model up for.

the genius of two-stage filtering:
tiny model = high recall, sometimes wrong.
frontier model = high precision, swallows false positives via wait.
user sees zero noise.

drafts before any outbound mutation

email send, calendar create/update/delete — all four routes through the same four-step pattern. enforced by prompt, no exceptions.

memory model

what's actually in the leak — two explicit blocks plus the implicit per-agent thread state. nothing more. (the "3-tier memory" framing some clones use is their invention.)

<summary> block

auto-injected when conversations grow long. compresses old history without throwing it away. user cannot see it. memory-guidelines.md:3

<user_context> block

injected per turn. carries name, connected accounts, "preferences, writing style, previous requests." may be wrong — model told not to rely solely on it. guidelines.md:19

per-agent thread state

each execution agent's own conversation history IS its private memory. accumulates across firings. addressable by name. no separate store needed.

no  remember() tool

"the system maintains memory automatically." when user says "remember this", agent just acknowledges — no explicit tool. memory-guidelines.md:13

the five load-bearing patterns

1 — strict personality / work separation

personality agent has zero work tools. execution agents have zero voice. enforced by two separate system prompts in two separate api calls. one turn = at minimum 2 anthropic calls.

2 — long-lived named sub-agents = task-scoped memory

prefer to send messages to a relevant existing agent rather than starting a new one… do this by referencing the existing agent_name. don't worry if this name is unrelated to the new task if it contains useful context. agent-protocol.md:52

3 — the wait tool = silent cancellation

the decision to activate a trigger is done by a very small model that sometimes makes mistakes… always use the wait tool to silently cancel. agent-protocol.md:19–21

4 — drafts mandatory before any outbound mutation

if the user asks you to forward, send, or reply… always confirm via display_draft before dispatching. agent-protocol.md:34–38

5 — single-entity illusion enforced in prompts, not architecture

maintain the illusion of being a single, unified entity. never reveal: technical processes or agent interactions, tool names, process steps. agent-protocol.md:3

donna's actual architecture

same scale, same notation, so the comparison is honest. one monolithic brain. one parallel watch substrate. shared transcript at the bottom.

three deliberate trade-offs

these aren't accidents. each is a call we made knowing the cost.

lessons earned (opinionated)

not a feature checklist. things we now believe after staring at the leak for too long.

the "single unified entity" illusion is a tax, not a feature

poke's prompt enforces it explicitly. their prompt leaked anyway in 7 days. the architecture is provably multi-agent; pretending otherwise costs prompt tokens, distorts error messages, and breaks the moment someone gets curious. donna doesn't pretend. the user can see, at /debug/runs, exactly what fired and why. that's a product feature.

two tiers is luxury, not necessity

poke needs the personality/work split because their tool catalog is enormous and they need voice consistency across 400k users. donna is one user, ~50 tools. the monolithic brain is the right call today. the day the tool list crosses 40 or the prompt blows past 6000 tokens, revisit. not before.

long-lived named threads is the real unlock

this is the one architectural pattern donna copied wholesale (today). every "ongoing thing" becomes a thread — a PR watch, a hydration tracker, a gratitude practice. state is free: the thread's own history IS its memory. no separate state schema, no scratchpad table. this is what makes "invent any feature on the fly" possible at all.

the wait pattern is a steal — borrow it next

donna's do_nothing persists the turn. poke's wait silently swallows false-positive triggers without polluting history. small surface — maybe 40 lines of code. enables the two-stage filtering pattern (tiny model decides fire, big model decides act) that drops proactive cost by ~10x. biggest single quick win remaining.

drafts before send is non-negotiable

poke mandates compose_draft → display_draft → user confirms → execute_draft for every outbound mutation. donna has no outbound email/calendar tools today, so this is a latent gap — not biting yet. the moment a send_email tool ships, drafts must come with it. no exceptions. this is how you avoid the "ai sent an email i didn't approve" incident every personal-ai eventually faces.

browser-use is the universal escape hatch

built today. with it, donna's feature surface goes from "what composio supports" to "anything a human can do in a browser." it's slow ($0.20, ~30s), error-prone, and last-resort — but the long tail of "find me a hotel under $250" / "watch this jacket's price" / "check if the LCBO is open" suddenly becomes possible. browser_use + watches is the cross-integration on-the-fly engine.

the shared transcript bet is the right one for us

poke walls watches off from user chat. donna's watches read it. for a multi-tenant agent factory, isolation is correct. for one user's whole life, coherence wins — donna in reactive shouldn't be ignorant of what donna told the user via a watch last night. we deliberately traded poke's strict abstraction for a more honest model of "one donna, many surfaces."

tiny classifier before big model — pay the haiku tax

poke filters trigger fires with a small model first, frontier model second. donna's current arbiter is rule-based (quiet hours + cooldown). adding a haiku-class classifier in front of scan_gmail causes (and email-match watches when they land) saves an order of magnitude in inference cost. cheap to add. high-leverage.
